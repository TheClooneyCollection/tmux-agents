# Recover agent identity when claiming a role

Role claims on agents started outside the launcher must populate a missing session
record kind. Inspect the pane process tree using the same ancestry check as
peers/connect, recognizing Claude, Codex and configured Codex profile executables.
Prefer the nearest recognized process so an executable profile wrapper retains its
name. Normal profile launches run a process named `codex`; map that process's
`CODEX_HOME` to the configured profile, using its environment from `ps -E` on
macOS or `/proc/PID/environ` on Linux. An unreadable or unmatched environment
keeps the ordinary `codex` kind.

Preserve existing record fields, including kind, conversation ID, name, directory
and depth. Recover a Claude resume UUID and
an explicit model argument when unambiguous; otherwise the board uses its default
model label. If no supported agent is detected, keep the existing role and tracking
behavior and report that the kind could not be detected. Do not infer identity
from unrelated processes or from the pane label.

Shell panes remain ineligible for role claims; the existing shell guard applies
before detection or tracking changes.
