# Starting agents through tmux-agents

**Context.** Agents started by hand (`claude`, `codex`) have no turn hooks. A `tmux-ask` request marks the receiver `working` and nothing ever ends it, so the list shows `working 16h · worked 16h22m` and "no report yet" for agents that finished long ago. Changing users' settings files to add hooks was rejected: tools must not edit them.

**Decision.**

- **`tmux-agents start claude|codex|<profile> [--name NAME [--exact]] [-- AGENT ARGS]`** starts a top-level agent in the current pane (not a sub agent or member).
  - It names the pane in the usual format, or uses `--name` with the given-name rules.
  - It pins the agent's identity the way `tmux-spawn` does: `-c shell_environment_policy...` for Codex, and `CODEX_HOME` for a profile from `@tmux_agents_codex_homes` or the env.
  - It passes the same turn hooks (Claude `--settings`) or notify (Codex `-c notify`) as `tmux-spawn`, so state and worked time are tracked.
  - Arguments after `--` go to the agent unchanged.
- **`tmux-agents start chain [DIR] [--worker AGENT]`** opens a new window in DIR (default `$PWD`), starts the main agent with `start claude`, and gives it "start the chain" (plus the worker choice). The agent-chain skill spawns the members, which already get hooks.
- **Untracked agents.** An agent without turn hooks isn't state-tracked:
  - its status is `-` instead of `working`;
  - it has no worked time;
  - a missing turn end never makes it "needs you".

  Messaging still works.
- **Codex wrappers stay**, as identity pinning only, for people who type `codex` directly. The docs and `install.sh`'s printed steps recommend `tmux-agents start` for tracking and make the wrapper optional.

**Layout update.** The user dropped launcher splitting in favor of manual pane splits or asking an agent to use `tmux-spawn --split`. The former split-connection question is removed; `start chain` still opens a new window.

**Open questions (defaults in bold).**

1. Does `start` in the current pane replace the shell (`exec`) or run the agent as a child? **Child: when the agent exits, the pane returns to the shell, and the agent's work is saved and the pane's agent state cleared, like a close.**
2. How is a pane known to be tracked? **`@tracked=1`, set by `tmux-agents start` and `tmux-spawn` before the agent runs, and also by the first `--turn-start`/`--turn-end`/notify report, so hooks configured some other way count too. Only tracked panes get `working` from `tmux-ask`.**
3. Permission mode? **The agent's own defaults. `start` doesn't add auto mode and is unaffected by the sub-agent `sub_auto` setting; pass permission options after `--` if wanted.**
4. Session records? **Yes, an agent ID and record (kind, dir, session id, worked time), so worked time survives a pane kill. No parent, so it isn't listed as a resumable sub agent; resume is the agent's own (`-- --resume`).**
5. How does `start chain` give the main agent "start the chain"? **As Claude's initial prompt argument, so no delivery timing is involved.**
6. What's the window named? **After DIR's basename; the main agent renames itself as the chain skill says.**

**Why.** A launcher gives hand-started agents the same tracking as spawned ones without touching anyone's settings files. An honest `-` beats a `working` that never ends.

**Rejected.** Editing `~/.claude/settings.json` or Codex `config.toml` to add global hooks (tools must not change users' settings). Guessing a turn end from pane output.

**Named-pane takeover (2026-10-06).** A name can outlive a directly started agent. When `start` runs with stdin's `tty` equal to the pane's `pane_tty`, it may take over that named pane from its shell. Keep the name and peer connections unless a different `--name` is supplied. After the tty gate and before cleanup, format that name with the usual launcher rules (`--exact` keeps it verbatim) and use the shared `tmux-rename` path, including its notices and identity-linked references. A taken or invalid name refuses without changing pane state or records; no name or an identical name skips renaming. Then close and announce the old identity when present, and clear the old per-agent state using the same cleanup as launcher exit, except the name and peers. Assign a fresh identity and record and start tracked and idle. Without a matching stdin terminal, refuse with instructions to quit the agent and run from the pane's shell or use a fresh pane. Do not infer agent liveness from `pane_current_command`.
